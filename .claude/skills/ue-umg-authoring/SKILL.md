# WBP 만들기

- **팩토리만으로는 루트 위젯이 없다.** `bUseWidgetTemplateSelector` 가 꺼져 있으면 `RootWidgetClass = DefaultRootWidget`(이 프로젝트는 없음)로 덮는다
  [소스 `WidgetBlueprintFactory.cpp:184`]. → `WidgetTree->ConstructWidget<UCanvasPanel>` + `RootWidget` 지정 + `OnVariableAdded`(§12-1 A7).
- **위젯 이름 → GUID 맵을 맞춘다.** 맵이 비어 있으면 컴파일러가 결정적 GUID 로 채우지만(`WidgetBlueprintCompiler.cpp:768`), 비어 있지 않은 WBP 에 위젯을 더하고
  알리지 않으면 `ensureAlways`(`:795`)가 터진다 [소스]. → 더할 때 `OnVariableAdded`, 지울 때 `OnVariableRemoved`, 이름을 바꿀 때 `OnVariableRenamed`(`WidgetBlueprint.h:259`).
- **트리를 고칠 때는 사본에 적용 → 역추출해 목표와 같은지 확인 → 같을 때만 바꿔 끼운다**(WidgetMcp 조정기). 원본을 손대지 않아 롤백이 구조로 보장된다.
- 부모에 필수 `BindWidget` 이 있으면 빈 캔버스는 컴파일되지 않는다 — 만들 때 컴파일을 건너뛰고 spec 을 적용할 때 컴파일한다.
- **슬롯 종류는 부모 타입이 정한다**(Canvas · Overlay · VerticalBox …). 생략한 값은 엔진 생성자 기본값이다 — Border 슬롯 padding (4, 2) 처럼 0 이 아닌 것이 있다
  (`core/spec.py` 기본값 표). 파이프라인은 다 채운 spec 을 보낸다.

# BindWidget · 생성 C++

- 생성 베이스(`AutoGen/`, 첫 줄 `// AUTO-GENERATED by uigen` 이 있을 때만 덮어씀) + 스텁(없을 때만 만들고 이후 사람 소유) 두 겹. 스텁 클래스 이름은 바꾸지 않는다 —
  WBP 의 부모 경로가 `/Script/AstralBreak.<클래스>` 다.
- **UHT 는 모듈 안에서 헤더 파일 이름이 겹치면 안 된다** — codegen 이 쓰기 전에 검사한다(`HEADER_NAME_TAKEN`).
- 계약(바인딩 목록)의 해시가 같으면 쓰기 · 빌드 · 재기동을 건너뛴다. 바인딩은 추가만 — spec 에서 빠지면 `BindWidgetOptional`, 위젯 클래스가 바뀌면 거부.
- **계약이 바뀐 뒤 지난 `/Game/_AutoGen/*` 의 같은 화면 WBP 를 열면 컴파일 오류가 난다**(그때의 바인딩이라 정상).
- 접히는 자리의 setter(`Set…Visible`)는 **칸 전체(상자)** 를 켠다 — 안쪽 그림만 켜면 빌드는 통과하고 게임에서 안 뜬다 [실측 — README '돌리기' 주의].
- 놓인 칸(`UserWidget`)은 **그 칸의 실제 C++ 부모 클래스**로 `BindWidget` 한다(`UUserWidget` 으로 묶으면 스텁이 칸의 setter 를 못 부른다). 클래스 · include 는 `core/cellref` 가 승격 기록 · `screens.yaml` 에서 얻고, 손으로 쓴 클래스의 헤더는 모듈 안의 `<클래스>.h` 하나.
- 버튼 묶기 = 생성 베이스 `NativeOnInitialized` 에서 `OnClicked().AddUObject(this, &ThisClass::Handle…Clicked)`(가상 함수 — 스텁이 재정의, 스텁이 `NativeOnInitialized` 를 재정의하면 `Super` 먼저). 생성 코드는 누름에 자기 모양을 안 바꾼다.
- 생성기에 조각을 더할 때는 **그 조각을 쓰는 계약에만** 해시가 들게 한다(`cppgen.generator_for` · `EXTRA` · `SCREEN_TEMPLATES`) — `SETTERS` 표나 기존 템플릿 4 개를 건드리면 두 HUD 의 계약 해시가 바뀌어 이어서 고치기가 `EDIT_CONTRACT_CHANGED` 로 막힌다.

# 오프스크린 렌더(`render_widget`)

- **색에 sRGB 가 한 번 더 걸린다.** `FWidgetRenderer(gamma=true)` + `CreateTargetFor(…, true)`(`WidgetRenderer.cpp:81` — `SRGB=false`)로 그리고, 읽은 8 비트 값에 채널마다
  sRGB → 선형을 **한 번** 하면 지정색이 나온다 [실측 3점]. `gamma=false` 는 어두운 쪽이 뭉개져 쓰지 않는다(§12-1 A6-색). 알파는 255(검은 바탕).
- 그릴 때마다 `FlushRenderingCommands` — 그래야 글꼴 · 텍스처가 다 올라온 그림을 읽는다. 2 번 그려 픽셀 차를 같이 낸다.
- **SDF 글꼴은 글리프를 작업 스레드에서 만들고 처음엔 자리표시를 그린다**(`FontCache.cpp:1472` `SpawnWithPlaceholder`, `UpdateCache` 가 바꿔 넣음) [소스]. 에디터 틱이 안 도는
  함수 안에서는 미리 한 번 그리고 쉬며 `UpdateCache` 를 돌린다 — 호출마다 2 초다 [실측]. **상태를 여러 장 그릴 때는 `states[]` 한 호출로 묶는다**(준비 대기 한 번,
  76 장을 한 장씩 그린 것과 PNG 가 바이트까지 같음 [실측 11-24]).
- **머티리얼 셰이더는 첫 그리기에서야 컴파일을 시작하고, 컴파일 중인 배치는 그려지지 않는다.** 저장된 WBP 를 새 에디터에서 처음 그리면 고리(UI 머티리얼)가 빠졌다 [실측] →
  미리 그린 뒤 `GShaderCompilingManager->FinishAllCompilation()` 을 한 번 더.
- 화면 밖으로 완전히 나간 위젯(과 자식)은 Slate 가 그리지 않아 `GetPaintSpaceGeometry` 가 (0, 0, 0, 0) 이다 — '크기 0' 이 아니라 '안 그려짐'으로 센다.
- `force_visible` 은 **놓인 칸 속까지 들어가지 않는다** — `UWidgetTree::ForEachWidget` 은 자기 트리만 돈다(`WidgetMcpRender.cpp:239`). 칸은 처음 상태(접힌 것은 접힌 채)로 그려지고, 칸 안을 바꾸려면 덮어쓰기 열쇠 `칸/위젯`.
- 검정 바탕만 보면 알파 결함이 숨는다 — 투명도는 회색 · 흰 바탕에서도 본다(§11 'H3').
- 출력 폴더는 `[WidgetMcp] WidgetRenderOutputRoots`(= `Tools/uigen/work/`) 아래 새 · 빈 폴더만. `Saved/` 는 사람도 도구도 못 읽어 쓰지 않는다.

# 텍스처 · 브러시

- Interchange 기본 텍스처 파이프라인은 **2 의 거듭제곱이 아닌 크기를 걸러 낸다**(`bAllowNonPowerOfTwo = false` `InterchangeGenericTexturePipeline.h:70`) → 트랜지언트로 복제해 켠다.
  임포트 뒤 압축 · 그룹(UI) · 밉 없음 · `NeverStream`(`StreamableRenderAsset.h:299`) · sRGB 를 넣고 컴파일을 끝낸 다음 그린다.
- 5.7 에서 `TC_EditorIcon` 의 표시 이름은 `Uncompressed (RGBA8)` 다(`TextureDefines.h:400` — 엔진은 BC7 을 권함). 큰 바탕만 BC7.
- **box 9-slice 의 모서리 두께 = 텍스처 픽셀 × margin**(`ElementBatcher.cpp:857`) — 텍스처가 2 배면 모서리도 2 배로 그려지고 가운데가 눌린다. 크기가 고정된 위젯은 `image` 로 그린다.
- 겹치지 않게 나눈 두 텍스처를 엔진이 따로 늘리면 경계에 검은 절취선이 생긴다 — 투명 픽셀의 색도 가장 가까운 보이는 색으로 채운다(§11 'I 후속').
- ProgressBar 는 `Mask` 면 진행률에서 곧게 자르고 `Scale` 이면 그림 전체를 늘린다. 배경 브러시에 채움과 같은 텍스처를 물들여 넣으면 '빈 자리'가 된다(모양 막대).
- 위젯 회전이 필요한 런타임 아이콘(마름모)은 아직 어휘가 없다.

# 글자

- 한글은 프로젝트 폰트(`F_Pretendard_W` · `F_NotoSerifKR_W`)로. 엔진 기본 글꼴은 한글 bold 가 굵어지지 않는다 [실측]. 빛(`font.glow`)은 SDF 사본(`*_SDF`)이 있어야 한다 —
  `bEnableDistanceFieldFontRasterization` · `UI.SlateSDFText.RasterizationMode=Msdf`(`Config/DefaultEngine.ini`).
- 빛은 글자 상자를 사방 size 만큼 키운다 — 슬롯 padding 을 그만큼 줄인다(음수). 가운데 정렬의 오프셋 = (할당 − 자식)/2 + 앞 여백 − 뒤 여백(`LayoutUtils.h:664`)이라
  자리를 옮길 때 padding 을 양쪽 ± 로 나눈다.
- **말줄임(`ETextOverflowPolicy::Ellipsis`)은 글자 상자가 아니라 잘라 내는 사각형에서 정해진다**(`ElementBatcher.cpp:1633` — ScissorRect 가 없으면 아무 일도 없다 [소스 · 실측]) → `Clipping = OnDemand` 를 같이 건다(넘칠 때만 자름).
  **가운데 정렬 글자는 엔진이 줄이지 않는다**(`SlateTextLayout.cpp:169` — Center 는 NoOverflow) — 왼쪽 · 오른쪽 정렬로. 폭이 정해진 칸이어야 하므로 슬롯은 채움(`h_align fill`)이나 고정 크기.
- **작은 글자(획 13 px)는 같은 글꼴도 다시 재면 획 밀도가 ± 15 % 흔들린다** [실측] — 우리가 그린 참고판의 글꼴 값은 `text_ref_layout.yaml` 이 정한다(다시 재지 않음).

# 클릭을 받는 화면(Phase 3-3)

- **Image · TextBlock · ProgressBar 의 기본 보이기는 `visible` 이라 아무것도 안 해도 클릭을 먹는다.** 나중에 그려진 것이 먼저 받는다 — 버튼 위 장식은 `HitTestInvisible`, 패널은 `SelfHitTestInvisible`. `HitTestInvisible` 조상은 자식까지 막아 그 안의 버튼이 죽는다.
- 파이프라인은 클릭을 받는 화면 종류(프로필 `input_rules`)에서 **정규화의 기본값**으로 정한다(`core/spec.default_visibility`) — layer · refine · fix 가 나중에 더하는 위젯도 같은 규칙을 탄다. spec 에는 안 적힌다. 확인은 역추출한 트리로(`core/hit` · 게이트 `input_clear`) — 엔진 히트 테스트는 아니다.
- 버튼 칸(`UCommonButtonBase`)의 `UserWidget` 자신은 `SelfHitTestInvisible`, 안쪽 버튼이 받는다. 버튼 아닌 칸은 `HitTestInvisible`(속의 그림까지 안 받게).

# 디자이너 · 저장 · 승격

- UMG 디자이너는 Visibility 를 무시하고 늘 보이게 그린다 — `bHiddenInDesigner` 만 본다 [소스 `Widget.cpp:1482`]. 접힌 위젯이 미리보기를 덮으면 spec `designer_hidden`.
- verify 를 통과할 때까지 저장하지 않는다. 쓰기는 `/Game/_AutoGen/<run_id>/`(git 무시)만, 승격은 `promote_widget` → `screens.yaml promote_path`(`/Game/UI/HUD` · `/Game/UI/Common` · `/Game/UI/Screens`)`/<화면>/`(**대상이 있으면 거절** — 재승격은
  `Tools/uigen/promote_screen.py apply` 가 에디터를 끈 채 사본을 두고 비운 뒤 부른다, 손으로 치우지 않는다).
- `IsValidLongPackageName("/Game")` 은 참이다 — 마운트 루트를 허용 목록으로 받지 않게 따로 막는다.
- `quit_editor` 는 더티면 거절한다. 파이프라인은 `discard_only_under: [/Game/_AutoGen/]` 만 준다.

# CommonButton · 칸(Phase 3-2)

- **진짜 버튼은 안쪽 `SCommonButton`** — `UCommonButtonBase` 의 `WidgetTree->RootWidget`(`InternalRootButtonBase`)의 Slate 는 크기 상자(SBox)이고 그 첫 자식이다. SBox 에 이벤트를 보내면 오류 없이 아무 일도 없다 [실측].
- 상태 그림은 `UCommonButtonStyle` **클래스 기본값**만 읽는다(`BuildStyles`). 일곱을 다 채운다 — `Disabled` 가 비면 Slate 가 기본 그림을 흐리게 그린다.
- **클래스 기본값을 컴파일 뒤에 고치면** `UBlueprintGeneratedClass::UpdateCustomPropertyListForPostConstruction()` 을 부른다 — 인스턴스는 컴파일 · 로드 때 만든 목록의 속성만 물려받아, 안 부르면 다음 컴파일까지 엔진 기본값으로 그려진다 [실측].
- `WidgetTree->ConstructWidget` 을 UUserWidget 클래스에 쓸 때는 `ConstructWidget<UUserWidget>` 갈래로(`CreateWidget` 을 타야 한다).
- 선택 모양은 `SetSelectedInternal`(protected) 로만, `bSelectable=false`(누름이 스스로 선택을 바꾸지 않게). 오프스크린 렌더에서만 `SetIsSelectable(true)` + `SetIsSelected`.
- 키보드 초점은 올림이 아니다 → `UAstralButtonBase` 가 방향키 초점에서 '기본' 브러시를 '올림' 브러시로 갈아 끼운다. 엔진 초점 테두리는 초점 위젯에서 바깥으로 올라가며 처음 답한 `OnQueryShowFocus` 를 따르므로, 버튼 하나만 막으려면 껍데기 위젯이 거짓을 답한다(전역 ini 불필요).
- 렌더 geometry 에는 칸 안 글자가 `칸/글자` 줄로 있다 — 놓은 화면이 글자를 정하므로(props) 칸 혼자 그린 자리를 쓰지 않는다.

# 게임에 연결한 조작 화면(Phase 3-4)

- **스텁은 에디터 렌더에서 아무것도 하지 않는다**(`!GetOwningPlayer() || !GetWorld()->IsGameWorld()` 면 돌아감) — 원천을 붙이거나 칸을 바꾸면 승격 `record` · `status` 의 그림이 달라져 기록이 깨진다. 게임에서는 놓인 칸의 처음 상태가 컨셉 상태(보기 이름 · 표시 켬)라 첫 갱신이 모든 칸을 정한다(빈 자리는 접기).
- **클래스 생성자(기본 객체)에서 `FUIActionTag::ConvertChecked` 금지** — 모듈을 올릴 때는 태그 관리자가 'UI.Action' 뿌리를 아직 몰라 맞는 태그도 `check` 에 걸린다 [소스 `UITag.h` `TryConvert`]. 이름만 옮기는 `AstralGameplayTags::MakeUIActionTag`. 런타임(`NativeOnInitialized` 등)의 `ConvertChecked` 는 괜찮다.
- 여는 키는 맵 GameState 의 `ContextScreens`(루트 레이아웃이 **Game 입력에서만** 묶음), 같은 키로 닫기는 화면 자기 묶음(기본 Menu 입력) — 위에 다른 화면이 있으면 그 키는 아무것도 안 한다.
- **편집기 다중 창 PIE: 입력 설정이 한 창에만 걸린다** — 라우터는 화면이 켜질 때 초점이 있던 창에서만 설정을 걸고 나중에 초점이 와도 다시 걸지 않는다 [소스 `UIActionRouterTypes.cpp` `ApplyLeafmostNodeConfig` · `IsViewportWindowInFocusPath`]. PIE 시작 때 초점은 마지막에 만든 창뿐이라, 다른 창은 설정이 없는 채(`GetActiveInputMode` = All)이고 Game 전용 묶음(Tab)이 안 먹는다 [실측]. 시험은 그 창에 초점을 준 뒤 루트 레이아웃을 껐다 켠다. 쿠킹 게임에는 없고, 사람 확인은 한 창 PIE · `-game` 으로.
- **PIE 창이 작으면 화면이 창 밖으로 잘린다** — 짧은 변 480 px 이하에서 화면 배율이 바닥 0.444 에 걸린 채 더 줄지 않아 1920 × 1080 화면의 아래 · 오른쪽 버튼이 창 밖으로 나가고 히트 테스트 · 방향키가 못 닿는다 [실측 568 × 365]. 시험 창은 16:9 960 × 540(배율 0.5).
- **게임패드 A = 실제 커서 자리의 마우스 클릭** — `CommonUI.ShouldVirtualAcceptSimulateMouseButton` 기본 켜짐, 커서는 초점 버튼 가운데로 옮겨 간다(`CommonAnalogCursor.cpp`). 한 프로세스 다인 PIE 에서 다른 창이 그 자리를 덮으면 그 창이 받는다 — 시험은 덮는 창을 옆으로 옮긴다. 마우스 클릭 시험은 그 자리 창만 히트 테스트(`LocateWindowUnderMouse(위치, {그 창})` → `RoutePointer…Event`)해 겹쳐도 된다.
- 마우스 클릭 시험: 이동 · 눌림 · 뗌을 **한 틱 안에서** 흘린다(다음 틱에 Slate 가 실제 커서 자리로 이동을 지어내 올림이 풀린다). 꺼진 버튼은 히트 길에서 잘린다(`bIgnoreEnabledStatus=false`) — '가리는 것 없음'은 꺼짐 무시 길로 따로 본다. 빈 길(창 밖 · 안 그려짐)을 '가렸다'로 치지 않는다.
