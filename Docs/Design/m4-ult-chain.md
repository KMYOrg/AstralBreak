# M4 오의 + 체인 버스트 설계

작성일: 2026-11-13 · 대상: UE 5.7.4 · 기준 커밋: `2aea26c`(+ M3 뒤 다듬기 미커밋) · 기획 원문: [game-plan.md](game-plan.md) M4 절 · 앞 단계: [m3-enemy-ai.md](m3-enemy-ai.md)
상태: **설계 승인(2026-11-13, "단위 A 착수") · 단위 A 구현 · 자동 검증 완료(미커밋, 결과는 [§6](#단위-a-구현-결과-2026-11-13)) — 남은 것 = 단위 A 눈 확인(사용자). 단위 B ~ E 미착수.**

M4(오의 · 체인 버스트)의 설계를 이 문서 하나에 쌓는다. 참고작은 그랑블루 판타지 리링크다(사용자 지정, 2026-11-13) — 규칙의 뼈대를 이해하는 용도이고 복제 대상이 아니다.

**표기:** **[소스]** = 프로젝트 · 엔진 소스를 읽어 판단했고 실행하지 않았다. **[조사]** = 공개 공략 글에서 확인했다. **[기억]** = 작성자의 기억이고 출처로 확인하지 못했다. **잠정** = 기획 값이라 데이터에 두고 언제든 바꾼다([game-plan.md](game-plan.md) 정정 8).

## 1. 기획 다듬기 — 계획서와 달라지는 것

계획서 M4 절의 범위 · 리스크 · 예약은 그대로 선다. 아래는 원문이 비워 둔 곳을 채우거나 좁힌 것이다. **전부 제안이고, 값은 전부 잠정이다.**

| # | 계획서 | 다듬은 안 | 이유 |
| ---: | :--- | :--- | :--- |
| 1 | 게이지 수급 '일반 공격 / 피격 / **기여도**' — 기여도의 정의 없음 | 기여도 = **아군이 오의를 쓰면 나머지 팀원 게이지 +10** | 참고작의 규칙이고, 체인이 이어지게 만드는 장치다. 적중 · 피격 · 패링 수급은 이미 있다 [소스] |
| 2 | '짧은 시간 안에 연달아' — 윈도우 규칙 없음 | 첫 오의가 윈도우를 열고, 이어질 때마다 다시 잰다. 한 사람은 한 체인에 한 번. 4명이 차면 바로 닫는다 | §3 |
| 3 | '2 · 3 · 4인 연계별 효과 강화' — 효과의 실체 없음 | 둘레의 적에게 광역 피해. 인원이 늘수록 총 피해 배수가 오른다 | §3. Break 가 생기는 M5 뒤에 다시 본다 |
| 4 | 오의 중 피격 규칙 없음 | 오의를 쓰는 동안 무적 | §2 |

| 7 | 종료 조건에 AI 활용 산출물 없음(부록 D 2번) | 한 줄 더한다 — 오의 애니는 생성 파이프라인으로, 체인 판정은 자동 시험으로 | 정정 1 |
| 8 | 오의 · 체인 버스트 피해로 게이지가 차는가 — 언급 없음 | 차지 않는다 | 쓰자마자 다시 차면 체인이 끝없이 돈다 |

## 2. 오의 — 한 사람이 쓴다

### 결정

- **어빌리티** `UAstralGA_Hero_Ult`(`UAstralGA_Hero_Base` 파생 · 로컬 예측 · 액터당 인스턴스). `UAstralGA_Hero_MarkFinisher` 와 같은 뼈대다 — 비용 확정 → 몽타주 → 판정 → 종료.
- **입력** 새 태그 `InputTag.Ult` + 입력 액션 `IA_Ult`. 키는 구현 때 지금 배치를 보고 정한다(§8).
- **비용** 표준 Cost GE 한 개(`GE_Cost_Ult`): `UltGauge` 에 `MaxUltGauge × −1` 을 더한다(속성 기반 크기). 엔진의 비용 검사는 '적용한 뒤 0 미만이면 거부' 라서 **게이지가 가득일 때만 통과한다** — 검사용 코드를 따로 쓰지 않는다 [소스]. 최대치가 빌드로 바뀌어도 맞는다.
- **무적** 활성 중 태그 `State.Invulnerable`. `UAstralCombatStatics::ResolveIncomingDamage` 맨 앞에서 이 태그가 있으면 피해를 무효로 돌린다(패링 · 가드 통지 없음). 회피 무적은 여전히 범위 밖이지만 같은 태그를 나중에 쓸 수 있다.
- **다른 행동과의 관계** 발동하면 진행 중인 공격 · 방어 · 회피를 취소하고, 켜져 있는 동안 다른 어빌리티를 막는다. 방어 진입이 오의를 취소하지 못하게 예약 태그 `Ability.Behavior.SurvivesDefenseCancel` 을 단다(이 태그는 'M4 오의' 용으로 이미 선언돼 있고 쓰는 곳이 없다 [소스]).
- **전투 스타일에 묶지 않는다.** 근접 · 원거리 어느 모드에서도 쓴다. 판정은 무기 트레이스가 아니라 몽타주의 이벤트 시점에 전방 스윕(`ApplyDamageSweep`) 한 번 — 들고 있는 무기와 무관하다.
- **값(잠정)** 피해 200(강화 공격 60), 스윕 거리 400 · 반경 150, 오의 적중으로는 게이지가 차지 않는다.
- **서버 등록** 서버에서 비용 확정이 성공한 직후 체인 컴포넌트에 알린다(§3). 클라이언트의 예측 활성화는 등록하지 않는다.

### 대안과 기각 이유

| 대안 | 기각 이유 |
| :--- | :--- |
| 게이지 검사를 `CanActivateAbility` 에 직접 쓴다 | 표준 비용 경로가 이미 같은 일을 한다. 강화 공격(표식 소비)과 방식이 갈린다 |
| 무적을 `IncomingDamageMultiplier = 0` GE 로 | 패링 · 가드 통지가 그대로 나가 방어 보상이 새고, M7 빌드가 같은 속성을 곱하면 뜻이 섞인다 |
| 오의를 근접 모드 전용으로 | 원거리 모드에서 체인 창을 놓친다. 전환은 영웅별 특성이라(정정 4) 오의의 전제로 삼지 않는다 |

### 미해결

- **락온 방향 맞춤.** 강화 공격은 발동 때 락온 타깃 쪽으로 도는 세션(`UAstralFacingSession`)을 쓴다. 오의도 같아야 자연스럽지만 코드가 길다. 구현 때 강화 공격의 것을 베이스로 끌어올릴 수 있는지 보고, 안 되면 단위 A 는 방향 맞춤 없이 낸다.
- **오의 몽타주.** 단위 A 는 강화 공격 몽타주를 임시로 쓴다. 전용 애니는 단위 D.

## 3. 체인 판정 — 팀이 잇는다

### 결정

- **소유자** 새 `AAstralRaidGameState`(`AAstralGameState` 파생) + 복제 컴포넌트 `UAstralChainBurstComponent`. 지금은 레이드용 GameState 가 없다(주석에만 'M3+' 로 예약 [소스]). 레이드 · 전투 시험 맵의 GameMode BP 가 이 클래스를 지정한다. M5 의 보스 상태, M6 의 목표 · 결과가 얹힐 자리이기도 하다.
- **판정 로직은 순수 구조체 `FAstralChainTracker`** 로 떼어 낸다 — 입력은 (참가자, 시각), 출력은 상태와 '버스트 N명'. 월드 없이 단위 시험한다. 컴포넌트는 타이머 · 복제 · 피해만 맡는다.
- **규칙**

  | # | 규칙 | 값(잠정) |
  | ---: | :--- | :--- |
  | 1 | 체인이 없을 때 누가 오의를 쓰면 체인이 열린다 | — |
  | 2 | 열려 있는 동안 다른 사람이 쓰면 참가자에 더하고 마감을 다시 잰다 | 마감 = 마지막 등록 + 6.0초 |
  | 3 | 같은 사람의 두 번째 등록은 무시한다 | — |
  | 4 | 참가자가 4명(또는 살아 있는 파티 전원)이면 바로 닫는다 | — |
  | 5 | 닫힐 때 참가자가 2명 이상이면 체인 버스트, 1명이면 조용히 끝난다 | — |
  | 6 | 버스트는 마지막 오의의 연출이 끝난 뒤에 나간다 | — |
  | 7 | 서버는 마감보다 조금 늦게까지 받는다 — 마감 직전에 누른 입력이 지연으로 늦게 도착해도 인정 | 유예 0.25초 |
  | 8 | 버스트가 나가는 동안 들어온 오의는 다음 체인의 첫 번째다 | — |

- **경합** 등록은 서버의 한 스레드에서 비용 확정 순서대로 일어난다. 같은 틱에 둘이 와도 둘 다 들어가고, 인원은 참가자 배열의 크기다 — 계획서의 '정확히 N명' 은 여기서 정해진다.
- **팀 게이지** 등록 때 본인을 뺀 살아 있는 히어로 전원에게 게이지 +10. 기존 수급 경로(`ApplyUltGainToSelf`)를 써서 `UltGainMultiplier` 가 그대로 곱해진다.
- **버스트 피해** 마지막 참가자를 중심으로 반경 1000 안의 적 전부. 총 피해 = 300 × 인원 배수(2명 1.0 · 3명 1.6 · 4명 2.5). **총 피해를 참가자 수로 나눠 각자의 이름으로 넣는다** — 그래서 각자의 `OutgoingDamageMultiplier` 와 위협이 개인별로 계산되고, 새 예약 속성 `ChainBurstDamageMultiplier`(기본 1.0, 계획서의 '체인 버스트 기여도 Multiplier')도 자기 몫에만 곱해진다.
- **복제** 컴포넌트가 상태 하나를 복제한다 — 체인 번호 · 단계(없음 / 열림 / 버스트) · 참가자 목록 · 마감 시각(서버 시간) · 마지막 버스트의 인원. 버스트 통지도 멀티캐스트가 아니라 이 상태의 변화로 보낸다(늦게 받거나 한 번 놓쳐도 최신 값이 온다).
- **값은 전부 컴포넌트의 프로퍼티**다 — 레이드 GameState BP 에서 고친다.

### 대안과 기각 이유

| 대안 | 기각 이유 |
| :--- | :--- |
| 공용 `AAstralGameState` 에 직접 넣는다 | 허브에도 체인 상태가 생긴다. 지금 구조가 허브 / 레이드 상태를 클래스로 가른다 |
| 오의 어빌리티끼리 서로를 찾아 판정한다 | 판정의 주인이 없어 순서 · 중복 문제가 어빌리티마다 흩어진다 |
| 버스트 피해를 한 사람(마지막 참가자) 이름으로 | 위협이 한 사람에게 몰리고, M7 의 개인 빌드 배수가 팀 피해 전체에 곱해진다 |
| 윈도우를 '첫 오의부터 고정 N초' 로 | 넷째 사람의 여유가 앞사람들의 속도에 달린다. 참고작처럼 이어질 때마다 다시 재는 쪽이 4인 체인에 관대하다 |
| 유예 없이 서버 도착 시각으로만 | 지연이 큰 사람이 화면으로는 제때 눌렀는데 떨어진다(계획서의 '판정 공정성' 리스크) |

### 미해결

- 버스트의 중심(마지막 참가자 / 첫 참가자의 타깃 / 참가자들의 가운데) — 잠정은 마지막 참가자.
- 체인 도중 참가자가 죽거나 나가면: 인원에는 남기고, 그 사람 몫의 피해는 남은 참가자가 나눠 넣는다(잠정).
- 죽은 플레이어의 게이지는 그대로 둔다(잠정) — 부활 규칙이 생길 때 다시 본다.

## 4. 차단 훅 — M5 의 Burst Aura 가 얹힐 자리

- 태그 `State.Ult.Blocked` 를 오의 어빌리티의 발동 차단 태그에 넣는다. M5 는 Burst Aura 동안 히어로들에게 이 태그를 주는 효과를 걸면 된다.
- 효과가 준 태그는 복제되므로 **클라이언트도 발동 전에 안다** — 예측 발동 뒤 서버가 되돌리는 어색함이 없다. 서버 검증은 그대로 남는다(서버의 발동 검사).
- 실패 알림: 엔진이 주는 '발동 실패' 통지를 HUD 가 받아, 차단 태그 때문이면 '오의 불가' 를 띄운다. 게이지 부족은 조용히 무시한다.
- M4 에서는 보스가 없으므로 디버그 명령으로 태그를 걸어 확인한다.
- 열린 체인 도중에 Burst Aura 가 시작되면 체인을 버리는가는 M5 에서 정한다.

## 5. HUD — 처음 생기는 플레이어용 화면

- `UAstralCombatHUDWidget`(C++ 베이스 + WBP). 지금 플레이어용 UI 는 디버그 위젯 하나뿐이다 [소스].
- 보이는 것: 오의 게이지(가득 차면 강조) · 체인 패널(남은 시간 · 참가 N/4) · 버스트 배너(인원) · '오의 불가'.
- **화면은 상태를 갖지 않는다**(계획서 공통 원칙). 게이지는 속성 변화 통지, 체인은 컴포넌트의 상태 변화 통지, 남은 시간은 서버 시간에서 계산한다.
- CommonUI 는 켜지 않는다 — 메뉴 · 결과 화면이 생기는 M6 에서 다시 본다.

## 6. 구현 단위 — 수직으로 자른다

| 단위 | 내용 | 끝나면 보이는 것 | 검증 |

**설계와 달라진 것**

- **비용 GE 를 BP 애셋이 아니라 네이티브 클래스로 뒀다.** '전부 쓴다' 는 규칙이 데이터로 바뀔 일이 없고, 속성 기반 크기를 애셋으로 저작하면 틀리기 쉽다. 바꾸려면 GA BP 의 비용 GE 를 갈아 끼운다(사격 자세 GE `UAstralGE_RangedAimHold` 와 같은 선례).
- **오의는 영웅 세트(`DA_AbilitySet_Vesper`)가 준다.** 강화 공격은 무기(낫) 세트가 주는데, 오의는 무기가 아니라 영웅의 것이고 전투 스타일에 묶지 않기로 했다(§2).
- **asset tag 는 `Ability.Ult` 로 `Ability.Attack` 밖에 뒀고, 켜져 있는 동안의 태그에는 `Ability.Attack` 을 넣었다.** 안에 두면 다른 공격의 `BlockAbilitiesWithTag(Ability.Attack)` 에 걸려 콤보 도중 오의를 못 쓴다. 반대로 방어 · 스타일 전환의 '공격 중' 검사는 켜져 있는 태그를 보므로 거기에는 넣었다.
- **락온 방향 맞춤은 넣지 않았다**(§2 미해결 그대로). 지금 오의는 서 있는 방향으로 나간다. 임시 몽타주에 강화 공격용 워프 구간이 있지만 오의가 워프 타깃을 주지 않으므로 아무 일도 하지 않는다.
