## 2. 오의 — 한 사람이 쓴다

### 결정

- **어빌리티** `UAstralGA_Hero_Ult`(`UAstralGA_Hero_Base` 파생 · 로컬 예측 · 액터당 인스턴스). `UAstralGA_Hero_MarkFinisher` 와 같은 뼈대다 — 비용 확정 → 몽타주 → 판정 → 종료.
- **입력** 새 태그 `InputTag.Ult` + 입력 액션 `IA_Ult`. 키는 구현 때 지금 배치를 보고 정한다(§8).
- **비용** 표준 Cost GE 한 개(`GE_Cost_Ult`): `UltGauge` 에 `MaxUltGauge × −1` 을 더한다(속성 기반 크기). 엔진의 비용 검사는 '적용한 뒤 0 미만이면 거부' 라서 **게이지가 가득일 때만 통과한다** — 검사용 코드를 따로 쓰지 않는다 [소스]. 최대치가 빌드로 바뀌어도 맞는다.
- **무적** 활성 중 태그 `State.Invulnerable`. `UAstralCombatStatics::ResolveIncomingDamage` 맨 앞에서 이 태그가 있으면 피해를 무효로 돌린다(패링 · 가드 통지 없음). 회피 무적은 여전히 범위 밖이지만 같은 태그를 나중에 쓸 수 있다.
- **다른 행동과의 관계** 발동하면 진행 중인 공격 · 방어 · 회피를 취소하고, 켜져 있는 동안 다른 어빌리티를 막는다. 방어 진입이 오의를 취소하지 못하게 예약 태그 `Ability.Behavior.SurvivesDefenseCancel` 을 단다(이 태그는 'M4 오의' 용으로 이미 선언돼 있고 쓰는 곳이 없다 [소스]).
- **전투 스타일에 묶지 않는다.** 근접 · 원거리 어느 모드에서도 쓴다. 판정은 무기 트레이스가 아니라 몽타주의 이벤트 시점에 전방 스윕(`ApplyDamageSweep`) 한 번 — 들고 있는 무기와 무관하다.
- **값(잠정)** 피해 200(강화 공격 60), 스윕 거리 400 · 반경 150, 오의 적중으로는 게이지가 차지 않는다.
- **서버 등록** 서버에서 비용 확정이 성공한 직후 체인 컴포넌트에 알린다(§3). 클라이언트의 예측 활성화는 등록하지 않는다.

### 대안과 기각 이유

| 대안 | 기각 이유 |
| :--- | :--- |
| 게이지 검사를 `CanActivateAbility` 에 직접 쓴다 | 표준 비용 경로가 이미 같은 일을 한다. 강화 공격(표식 소비)과 방식이 갈린다 |
| 무적을 `IncomingDamageMultiplier = 0` GE 로 | 패링 · 가드 통지가 그대로 나가 방어 보상이 새고, M7 빌드가 같은 속성을 곱하면 뜻이 섞인다 |
| 오의를 근접 모드 전용으로 | 원거리 모드에서 체인 창을 놓친다. 전환은 영웅별 특성이라(정정 4) 오의의 전제로 삼지 않는다 |

### 미해결

- **락온 방향 맞춤.** 강화 공격은 발동 때 락온 타깃 쪽으로 도는 세션(`UAstralFacingSession`)을 쓴다. 오의도 같아야 자연스럽지만 코드가 길다. 구현 때 강화 공격의 것을 베이스로 끌어올릴 수 있는지 보고, 안 되면 단위 A 는 방향 맞춤 없이 낸다.
- **오의 몽타주.** 단위 A 는 강화 공격 몽타주를 임시로 쓴다. 전용 애니는 단위 D.

## 3. 체인 판정 — 팀이 잇는다

### 결정

- **소유자** 새 `AAstralRaidGameState`(`AAstralGameState` 파생) + 복제 컴포넌트 `UAstralChainBurstComponent`. 지금은 레이드용 GameState 가 없다(주석에만 'M3+' 로 예약 [소스]). 레이드 · 전투 시험 맵의 GameMode BP 가 이 클래스를 지정한다. M5 의 보스 상태, M6 의 목표 · 결과가 얹힐 자리이기도 하다.
- **판정 로직은 순수 구조체 `FAstralChainTracker`** 로 떼어 낸다 — 입력은 (참가자, 시각), 출력은 상태와 '버스트 N명'. 월드 없이 단위 시험한다. 컴포넌트는 타이머 · 복제 · 피해만 맡는다.
- **규칙**

  | # | 규칙 | 값(잠정) |
  | ---: | :--- | :--- |
  | 1 | 체인이 없을 때 누가 오의를 쓰면 체인이 열린다 | — |
  | 2 | 열려 있는 동안 다른 사람이 쓰면 참가자에 더하고 마감을 다시 잰다 | 마감 = 마지막 등록 + 6.0초 |
  | 3 | 같은 사람의 두 번째 등록은 무시한다 | — |
  | 4 | 참가자가 4명(또는 살아 있는 파티 전원)이면 바로 닫는다 | — |
  | 5 | 닫힐 때 참가자가 2명 이상이면 체인 버스트, 1명이면 조용히 끝난다 | — |
  | 6 | 버스트는 마지막 오의의 연출이 끝난 뒤에 나간다 | — |
  | 7 | 서버는 마감보다 조금 늦게까지 받는다 — 마감 직전에 누른 입력이 지연으로 늦게 도착해도 인정 | 유예 0.25초 |
  | 8 | 버스트가 나가는 동안 들어온 오의는 다음 체인의 첫 번째다 | — |

- **경합** 등록은 서버의 한 스레드에서 비용 확정 순서대로 일어난다. 같은 틱에 둘이 와도 둘 다 들어가고, 인원은 참가자 배열의 크기다 — 계획서의 '정확히 N명' 은 여기서 정해진다.
- **팀 게이지** 등록 때 본인을 뺀 살아 있는 히어로 전원에게 게이지 +10. 기존 수급 경로(`ApplyUltGainToSelf`)를 써서 `UltGainMultiplier` 가 그대로 곱해진다.
- **버스트 피해** 마지막 참가자를 중심으로 반경 1000 안의 적 전부. 총 피해 = 300 × 인원 배수(2명 1.0 · 3명 1.6 · 4명 2.5). **총 피해를 참가자 수로 나눠 각자의 이름으로 넣는다** — 그래서 각자의 `OutgoingDamageMultiplier` 와 위협이 개인별로 계산되고, 새 예약 속성 `ChainBurstDamageMultiplier`(기본 1.0, 계획서의 '체인 버스트 기여도 Multiplier')도 자기 몫에만 곱해진다.
- **복제** 컴포넌트가 상태 하나를 복제한다 — 체인 번호 · 단계(없음 / 열림 / 버스트) · 참가자 목록 · 마감 시각(서버 시간) · 마지막 버스트의 인원. 버스트 통지도 멀티캐스트가 아니라 이 상태의 변화로 보낸다(늦게 받거나 한 번 놓쳐도 최신 값이 온다).
- **값은 전부 컴포넌트의 프로퍼티**다 — 레이드 GameState BP 에서 고친다.

### 대안과 기각 이유

| 대안 | 기각 이유 |
| :--- | :--- |
| 공용 `AAstralGameState` 에 직접 넣는다 | 허브에도 체인 상태가 생긴다. 지금 구조가 허브 / 레이드 상태를 클래스로 가른다 |
| 오의 어빌리티끼리 서로를 찾아 판정한다 | 판정의 주인이 없어 순서 · 중복 문제가 어빌리티마다 흩어진다 |
| 버스트 피해를 한 사람(마지막 참가자) 이름으로 | 위협이 한 사람에게 몰리고, M7 의 개인 빌드 배수가 팀 피해 전체에 곱해진다 |
| 윈도우를 '첫 오의부터 고정 N초' 로 | 넷째 사람의 여유가 앞사람들의 속도에 달린다. 참고작처럼 이어질 때마다 다시 재는 쪽이 4인 체인에 관대하다 |
| 유예 없이 서버 도착 시각으로만 | 지연이 큰 사람이 화면으로는 제때 눌렀는데 떨어진다(계획서의 '판정 공정성' 리스크) |

### 미해결

- 버스트의 중심(마지막 참가자 / 첫 참가자의 타깃 / 참가자들의 가운데) — 잠정은 마지막 참가자.
- 체인 도중 참가자가 죽거나 나가면: 인원에는 남기고, 그 사람 몫의 피해는 남은 참가자가 나눠 넣는다(잠정).
- 죽은 플레이어의 게이지는 그대로 둔다(잠정) — 부활 규칙이 생길 때 다시 본다.

- '맞혔다' = 오의 판정(전방 스윕)에 적이 한 명이라도 걸렸다.
- '아무 일 없음' = 체인 참가도, 팀 게이지 +10 도, 타이머도 없다.
- 동시에 누르면 서버에 먼저 도착한 쪽만 나간다. 늦은 쪽은 발동되지 않고 게이지를 그대로 갖는다.

**오의 한 번의 흐름(바꾼 뒤)**

1. 입력 → 서버의 발동 검사. 다른 사람이 쓰는 중이면 차단 태그로 거부된다(게이지 유지).
2. 비용 확정(게이지 0) → 체인 컴포넌트에 '시전 시작' 을 알린다: 나머지 히어로에게 차단을 걸고, 열려 있는 체인이 있으면 **타이머를 멈춘다**(연출 중에 마감이 오지 않게).
3. 타격 이벤트 → 서버 스윕. 걸린 적의 수를 어빌리티가 기억한다.
4. 오의 종료(서버) → 차단을 풀고:
   - **맞혔다:** 그 시각으로 체인에 등록한다(열거나 들어간다, 마감 = 지금 + 윈도우). 나머지 살아 있는 히어로에게 팀 게이지 +10.
   - **못 맞혔다(판정 전에 끊긴 것 포함):** 최대치 × 0.8 을 돌려준다. 등록 · 팀 게이지 없음. 멈춰 둔 체인이 있으면 **멈출 때 남아 있던 시간으로** 타이머를 다시 돌린다.

**따라서 바뀌는 것**

- **규칙 6 이 단순해진다.** 등록이 오의 끝에 일어나고 연출 중에는 타이머가 멈추므로, 체인이 닫히는 순간 연출 중인 사람이 없다 — 버스트는 닫힌 직후(다음 틱) 나간다. 단위 B 의 '참가자 전원의 오의 종료를 태그로 기다리는' 장치는 필요 없어진다.
- **팀 게이지 시점이 '확정된 오의마다' 에서 '맞힌 오의가 끝날 때' 로 간다.** 거의 찬 사람의 게이지가 타이머가 도는 바로 그때 찬다.
- **윈도우 6초가 온전히 판단 시간이 된다**(연출이 깎지 않는다). 길면 값을 줄인다.
- **규칙 7(유예)은 그대로다.** 마감 직전에 누른 입력이 서버가 닫기 전에 도착하면 2번에서 타이머가 멈춘다.
- **복제 상태에 '누가 쓰는 중인가' 와 '타이머가 멈췄는가 · 남은 시간' 이 더해진다** — 단위 C 의 HUD 가 '○○ 시전 중' · 멈춘 타이머 · 도는 타이머를 구분해 보여 줄 수 있어야 한다.

**구조 메모**

- **80 % 반환은 오의 어빌리티의 규칙이다**(체인 컴포넌트가 없는 맵에서도 같다). 값은 어빌리티의 프로퍼티(`MissRefundRatio` 0.8). 반환은 수급 경로(`UltGain` 메타)를 타지 않는다 — `UltGainMultiplier` 가 곱해지면 안 되고, '오의로는 게이지가 차지 않는다'(§1 의 8번)의 유일한 예외다.
- **차단은 복제되는 효과(GE)로 건다** — §4 의 훅 그대로. 받는 사람의 클라이언트가 발동 전에 알아야 예측 발동 뒤 되돌림이 줄어든다. 디버그 `SetUltBlocked` 의 루즈 태그와 같이 있어도 된다(태그 수가 더해진다).
- **'오의가 끝났다' 는 이벤트로 안다**(폴링 없음). 쓰는 사람이 나가도 차단이 풀리고 멈춘 타이머가 다시 돌아야 한다 — 상한(잠정 10초, 단위 B 의 `BurstWaitTimeout` 자리)을 둔다.
- **판정 구조체**는 '멈춤 · 다시 돎' 을 받는다. 등록 시각의 뜻만 '누른 시각' 에서 '끝난 시각' 으로 바뀌고 규칙 1 ~ 5 · 7 · 8 은 그대로다.

**남는 어색함(알고 간다)**

- 동시에 누른 늦은 쪽의 클라이언트는 예측으로 동작이 잠깐 시작됐다가 서버 거부로 되돌아갈 수 있다(차단 효과가 복제되기 전에 누른 경우). 게이지는 되돌아온다.
- 살아 있는 사람이 혼자면 맞혀도 체인이 열리자마자 조용히 닫힌다(단위 B 와 같다).

**검증(줄인 범위)** — 판정 단위 시험에 멈춤 / 다시 돎을 더한다. 멀티 PIE 는 고쳐야 한다: 단위 B 의 체인 시험은 히어로가 **적을 등지고** 오의를 써서 버스트 피해만 쟀는데, 이제는 맞혀야 체인에 들어간다(적을 보고 쓰고, HP 계산에 오의 피해를 넣는다). 단위 A 의 오의 시험에는 '못 맞히면 80 % · 맞히면 0' 과 '남이 쓰는 동안 차단' 을 더한다. 그 뒤 `AstralBreak.` 전체 1회.

## 4. 차단 훅 — M5 의 Burst Aura 가 얹힐 자리

- 태그 `State.Ult.Blocked` 를 오의 어빌리티의 발동 차단 태그에 넣는다. M5 는 Burst Aura 동안 히어로들에게 이 태그를 주는 효과를 걸면 된다.
- 효과가 준 태그는 복제되므로 **클라이언트도 발동 전에 안다** — 예측 발동 뒤 서버가 되돌리는 어색함이 없다. 서버 검증은 그대로 남는다(서버의 발동 검사).
- 실패 알림: 엔진이 주는 '발동 실패' 통지를 HUD 가 받아, 차단 태그 때문이면 '오의 불가' 를 띄운다. 게이지 부족은 조용히 무시한다.
- M4 에서는 보스가 없으므로 디버그 명령으로 태그를 걸어 확인한다.
- 열린 체인 도중에 Burst Aura 가 시작되면 체인을 버리는가는 M5 에서 정한다.

1. **이미 참가한 사람이 같은 체인에서 또 맞힌 오의:** 참가는 무시하고(규칙 3), 멈췄던 타이머는 남아 있던 시간으로 다시 돈다 — 마감을 새로 재지 않는다. 팀 게이지 +10 은 준다.
2. **마감은 지났고 유예 안에서 시작된 시전이 못 맞히면:** 남은 유예만큼만 더 돌고 닫힌다(남은 시간이 음수인 채 멈춘다). 맞히면 정상 참가다.
3. **상한 `CastTimeout`(10초)이 종료 통지보다 먼저 나면:** 차단을 풀고 타이머를 다시 돌린다. 그 오의가 뒤늦게 끝났을 때 맞혔으면 그때 등록하고, 못 맞혔으면 80 % 반환만 한다.
4. **80 % 반환은 게이지 속성에 직접 더한다**(`ApplyModToAttribute`). 수급 경로를 타지 않아 `UltGainMultiplier` 가 곱해지지 않는다. 체인 컴포넌트가 없는 맵에서도 같다.
5. **차단은 네이티브 GE `UAstralGE_UltBlocked`** 를 시전 시작 때 그 순간의 나머지 전원(죽은 사람 포함)에게 걸고 끝날 때 걷는다. 시전 도중 새로 들어온 사람에게는 걸리지 않는다(지금은 난입 · 부활이 없다).
6. **'버스트' 단계는 한 틱짜리가 됐다.** 규칙 8(버스트 중 들어온 오의 = 다음 체인)의 코드는 남아 있지만 사실상 닿지 않는다. 클라이언트는 '열림 → 없음' 과 `LastBurstChainId` 의 변화만 본다고 보고 만들어야 한다(단위 C).
7. **스윕에 걸렸지만 피해가 0 인 경우(적 무적 · 패링)도 '맞혔다'** 로 센다.
8. (구현하며 정한 것 — 사전에 보이지 않았다) **누가 쓰는 중에 또 다른 시전 시작 통지가 오면**(차단을 받지 못한 사람 — 5번의 구멍) 앞 시전의 차단 · 멈춤은 그대로 두고 경고 로그만 남긴다. 그 오의도 맞혔으면 끝날 때 등록은 된다.
9. (구현하며 정한 것) **차단은 체인 컴포넌트의 일이다.** 컴포넌트가 없는 맵(허브)에서는 동시에 쓸 수 있다 — 80 % 반환만 어빌리티의 규칙으로 남는다.

**자동 검증 [실측]** — DebugGame 에디터, 한 프로세스 멀티 PIE, `CombatTestMap`. 입력은 각자 자기 자리의 ASC 에 입력 태그로 넣었다.

**실행 경과 — 한 번에 통과하지 않았다**

1. 첫 에디터: 오의 시험 2/2 통과, 체인 시험 0/2. 원인은 시험 구성이다 — '헛치는 사람' 을 자기 자리(클라이언트)에서만 돌려세웠더니 서버의 폰은 적을 본 채여서 실제로는 맞혔다(적 HP −250, 체인에 등록 — 규칙대로다). 서버 폰도 함께 돌리게 고쳤다 [실측: 서 있는 폰의 방향은 클라이언트에서 `SetActorRotation` 만 해서는 서버에 가지 않는다].
2. 둘째 에디터: `AstralBreak.` 전체 1회 — **53/55**(396초). 체인 시험 2개는 통과. 실패 2개는 오의 시험 리슨 · Dedicated 의 같은 단계였다 — 내가 더한 '자기 자리에 80 이 왔는가' 기다림이 기존의 `DamageSelf 10` 뒤에 있었고, 피격 수급으로 게이지가 이미 86.2 가 돼 있었다(첫 에디터에서는 우연히 80 을 먼저 봤다). 기다림을 피해 주입 앞으로 옮겼다.
3. 셋째 에디터: 오의 시험만 다시 — 2/2 통과.

- 따라서 **55개가 한 실행에서 모두 통과한 적은 없다.** 마지막 코드 기준으로 53개는 둘째 실행에서, 오의 시험 2개는 셋째 실행에서 통과했다. 둘째와 셋째 사이에 바뀐 것은 오의 시험 파일 하나(시험 단계 순서)뿐이다.
- 경고는 체인 · 오의 · 파티 흐름 시험의 `LogCrowdFollowing: Unable to find RecastNavMesh` 뿐이다. 에디터는 세 번 모두 `quit_editor`(저장 · 폐기 패키지 0) 뒤 프로세스 소멸 확인.

**돌리지 않은 것**

- 별도 프로세스 · 지연 주입(단위 E).
- **동시에 누른 경합.** 시험은 차단이 상대의 자기 자리에 복제된 뒤에 눌렀다 — 예측 단계에서 막힌 것이다. 차단이 복제되기 전에 눌러 서버가 거부하고 클라이언트가 되돌리는 경로(설계 절의 '남는 어색함')는 보지 않았다. 지연이 있어야 재현되므로 단위 E 의 몫이다.
- 상한 `CastTimeout` · 쓰는 사람의 이탈 · 조율되지 않은 둘째 시전(위 8번) — 코드만 있다.
- 판정 전에 끊긴 오의의 80 % 반환 — '적 없이 끝까지 쓴 오의' 로만 봤다.
- 중복 참가자 · 유예 안에서 시작한 시전 — 판정 단위 시험으로만 봤다.
- 체인 컴포넌트가 없는 맵(허브)에서의 오의와 반환, `RaidMap` 에서의 체인, 디버그 위젯 체인 줄의 화면 확인.

**사용자 눈 확인** — `CombatTestMap` 을 PIE 2인(리슨)으로 띄운다. `BP_Enemy_Melee` 는 오의 한 방에 죽으므로(피해 250, HP 100) **쓰기 직전에 자기 창에서 `SpawnEnemy` 를 한다**(내 앞 400 cm — 스윕 안이다).

1. 두 창에서 `FillUlt`. A 창에서 `SpawnEnemy` → `R`. **쓰는 동안** B 창의 `[Party]` 칸 체인 줄에 `Casting <A 의 id>` 가 보이고, B 창에서 `R` 을 눌러도 동작이 나오지 않으며 `ULT` 가 100 그대로다(`[Abilities]` 의 Tags 에 `State.Ult.Blocked`).
2. A 의 동작이 **끝난 뒤에** `Chain #1 Open 1/4 [...] 6.0s` 가 뜨고 그때부터 줄어든다. B 의 `ULT` 는 이미 100 이라 변화가 없다 — 팀 게이지를 보려면 B 를 채우지 않은 채로 한 번 더 해 본다(A 가 맞히고 끝날 때 +10).
3. 남은 시간 안에 B 창에서 `SpawnEnemy` → `R`. 쓰는 동안 체인 줄의 남은 시간이 멈추고 `(paused)` 가 붙는다. 끝나면 살아 있는 2명 전원이라 바로 `LastBurst #1 x2` 가 뜬다(버스트 피해 자체는 그 순간 반경 1000 안에 살아 있는 적이 있어야 보인다 — 오의에 맞은 적은 이미 죽어 있다).
4. 헛침: `FillUlt` 뒤 적이 없는 쪽을 보고 `R` → 동작이 끝나면 `ULT` 가 80 이 되고 체인 줄은 그대로다. 체인이 열려 있을 때 헛치면 `(paused)` 였던 남은 시간이 그 값에서 다시 줄어든다.

서버 로그에는 `[Chain] ult started by ...` · `... hit, ended at ...` · `... missed ...` · `burst #N xM` 줄이 남는다.

## 7. 종료 조건

1. 레이드 맵에서 4인이 체인 버스트까지 잇는다 — 모든 프로세스가 같은 인원 · 같은 적 HP 를 본다.
2. 3단계 네트워크(리슨 한 프로세스 · 리슨 별도 프로세스 · Dedicated) 통과.
3. 예약: 차단 태그 · `ChainBurstDamageMultiplier` · `UltGainMultiplier`(이미 있음).
4. AI 활용 산출물: 오의 애니(생성 파이프라인) · 체인 판정 자동 시험.
